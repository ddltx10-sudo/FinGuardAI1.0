# Развёртывание FinGuardAI

## Рекомендуемый вариант

Для Telegram-бота используется постоянный worker-сервис Railway. Telegram-бот не обязан иметь публичный HTTP-домен: он устанавливает исходящее соединение с Telegram API и постоянно работает как сервис.

## 1. Подключение GitHub

1. Откройте Railway.
2. Создайте новый проект.
3. Выберите развёртывание из GitHub Repository.
4. Выберите `Di-code-java/FinGuardAI`.
5. Используйте ветку `main`.

## 2. Запуск

В качестве команды запуска используется:

`python bot.py`

В репозитории уже добавлены `Dockerfile` и `Procfile`. Dockerfile использует Python 3.13 и запускает `bot.py`.

## 3. Переменные окружения

В настройках Railway добавьте:

`BOT_TOKEN`

`BINANCE_API_KEY`

`BINANCE_API_SECRET`

Значения должны быть настоящими секретами. Не добавляйте их в GitHub.

## 4. Постоянная работа

Telegram-бот должен работать как постоянный сервис, а не как периодическая задача. Railway поддерживает постоянные сервисы, которые продолжают работать после запуска.

## 5. Автоматическое обновление

После подключения GitHub Railway может автоматически разворачивать новые изменения при появлении новых коммитов в выбранной ветке `main`.

## 6. Публичная ссылка

Для Telegram-бота отдельная публичная HTTP-ссылка не требуется для обработки сообщений. Рабочей точкой взаимодействия является ссылка Telegram-бота вида:

https://t.me/ИМЯ_БОТА

Точное имя бота необходимо взять из BotFather или из уже зарегистрированного Telegram-бота.

При необходимости можно дополнительно создать публичный HTTP-сервис с endpoint `/health`, но для обычного polling-бота это не является обязательным.

## 7. Проверка после Deploy

После запуска необходимо открыть Deploy Logs и убедиться, что:

1. зависимости установились без ошибок;
2. `bot.py` запустился;
3. переменная `BOT_TOKEN` доступна приложению;
4. бот подключился к Telegram;
5. запросы к Binance API выполняются без ошибок;
6. бот отвечает на команды пользователя.

Если Deploy завершается сразу после запуска, необходимо проверить логи: это обычно означает ошибку импорта, отсутствующую зависимость, неверную переменную окружения или ошибку в `bot.py`.

## Важное замечание

В текущем репозитории конфигурация Deploy подготовлена, но рабочий Deploy нельзя считать завершённым до загрузки исходного `bot.py` и остальных файлов приложения. После загрузки кода необходимо проверить фактические импорты и обновить `requirements.txt` в соответствии с реальными зависимостями проекта.
